# USART3 反馈包格式

`Leader_f103c8t6`（STM32F103C8T6）从 USART3 发出的位置反馈包的完整规格。
发送实现在 [Core/Src/main.c](../Core/Src/main.c) 的 `SendFeedbackFrame()`，
看完这份不用读固件就能把包解出来。

---

## 1. 物理层

| 项 | 值 |
|---|---|
| 外设 | USART3 |
| TX / RX | PB10 / PB11 |
| 波特率 | 115200 |
| 帧格式 | 8 数据位 / 1 停止位 / 无校验（8N1） |
| 流控 | 无 |

适配器是 CH340，Linux 下固定走
`/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE8010651-if00`。
注意 `uart_check.py --list` 里还会列出 `/dev/ttyACM0`，**那不是这块板的串口**。

## 2. 包格式

一发一包，ASCII 文本行，**逗号分隔 + `\r\n` 结尾**：

```
<J1>,<J2>,<J3>,<J4>,<J5>,<J6>,<J7>\r\n
```

实例（`J1=211.7°`、`J2=238.9°`、…、gripper ADC = 500）：

```
2117,2389,635,2495,992,1245,500␍␊
```

7 个字段，**固定顺序，固定 7 个**。所有字段都是十进制整数，无空格。
前 6 个字段可能带负号，只有 `-1` 一种取值（见下方哨兵说明）。

### 字段定义

| # | 名称 | 含义 | 单位 | 有效范围 |
|---|---|---|---|---|
| 1 | `J1` | 关节 1 单圈角度 | 0.1° | `0..3599`，或 `-1` |
| 2 | `J2` | 关节 2 单圈角度 | 0.1° | `0..3599`，或 `-1` |
| 3 | `J3` | 关节 3 单圈角度 | 0.1° | `0..3599`，或 `-1` |
| 4 | `J4` | 关节 4 单圈角度 | 0.1° | `0..3599`，或 `-1` |
| 5 | `J5` | 关节 5 单圈角度 | 0.1° | `0..3599`，或 `-1` |
| 6 | `J6` | 关节 6 单圈角度 | 0.1° | `0..3599`，或 `-1` |
| 7 | `J7` | gripper 位置（ADC） | — | `0..1000` |

**前 6 个字段**是编码器读出来的单圈绝对角度，**除以 10 才是度数**：

```python
angle_deg = field / 10.0     # 2117 -> 211.7°
```

角度定义域是 `[0, 360)`，跨过 0° 会从 `3599` 直接跳回 `0` —— **这不是故障**，
是编码器本身就只有单圈信息。要做连续位置得自己在上位机做展开（unwrapping）。

**第 7 个字段**是 gripper 的位置反馈。它不是编码器，是 PA1 / ADC1_IN1 上的
12 位 ADC（`0..4095`）经下面这条链路换算来的：

```
adc_raw (0..4095)
  → /4095          归一化到 0..1
  → 一阶低通        系数 0.5，约 500Hz 更新
  → 死区压缩        0.4..0.6 这段被压平到正好 0.5
  → ×1000          变成 0..1000 的整数发出来
```

注意死区是**压缩**不是**截断**，量程没丢，两段各自线性映射：

| 输出 | 对应输入 |
|---|---|
| `0..500` | `0.0..0.4` |
| `500`（平的一段） | `0.4..0.6` |
| `500..1000` | `0.6..1.0` |

所以第 7 个字段**等于 500 时是平的**：输入在中间 20% 量程里怎么动，输出都是 500，
一点分辨率都没有。只有它离开 500 才说明 gripper 真的出了中间带。

### `-1` 哨兵：这一路没有数据

前 6 个字段可能出现 **`-1`**，含义是**"这个关节从来没有采到过一帧数据"**
（编码器没接、线断、或坏）。

它**不等于 0°**。固件里 `angles[]` 的初值就是 `-1.0f`，专门为了把这两种情况
分开 —— 否则一个没接的编码器会稳定显示 `0`，和一个真的停在零位的编码器长得
一模一样，排查时会直接把人带沟里。

解析时的正确做法：

```python
angle_deg = None if field < 0 else field / 10.0
```

注意 `-1` 只说明"从没成功过"。如果一个编码器采到过数据之后又断了，这个字段会
**冻结在最后一个有效值上**，不再变化 —— 光看数值区分不了"接着但静止"和"已经断了"。
要判活只能靠上位机自己看它动不动（见第 6 节）。

### 关节编号 vs 接线

包里的字段顺序永远是 **J1..J6、J7**，**不会因为换接线而改变**。
固件里有一张物理槽位 → 逻辑关节的映射表
（`encoder_slot_to_joint[]`），换接线只改那张表，包格式不变。这是刻意的：
上位机不会因为硬件重新插线而需要改代码。

当前接线：

| 关节 | 定时器/通道 | 引脚 |
|---|---|---|
| J1 | TIM2_CH1 | PA0 |
| J2 | TIM1_CH1 | PA8 |
| J3 | TIM2_CH3 | PA2 |
| J4 | TIM3_CH3 | PB0 |
| J5 | TIM3_CH1 | PA6 |
| J6 | TIM4_CH1 | PB6 |
| J7 | ADC1_IN1 | PA1 |

（TIM1_CH3 / PA10 那个槽位空着，这颗片子的 PA10 坏了。）

## 3. 速率与带宽

| 项 | 值 |
|---|---|
| 发包周期 | 5 ms（判据是 `HAL_GetTick()` 毫秒门，不依赖主循环节奏） |
| 发包频率 | 200 Hz |
| 单包长度 | 15..36 字节，随数值位数变（实测稳态约 33） |
| 占空比 | 至多 63%，按 115200 8N1 = 11520 B/s 算 |
| 内部刷新率 | 角度约 990 Hz（编码器 PWM 帧率），ADC 500 Hz |

**发送是"有则发、忙则跳过"**：上一包还没发完时这一拍直接丢弃，不排队、不补发。
所以 200 Hz 是上限，不是保证值。超过 63% 占空比再加负载就会静默丢包。

每个字段都是**该时刻的快照**，不是窗口平均、也不是积分。

## 4. 上电时序

板子复位后**第一件事**是发一行握手串：

```
0123456789\r\n
```

它**不是**合法的反馈包（字段数不对）。上位机要么显式跳过它，要么按"字段数不等于 7
就丢弃"处理。这一行可以用来判断板子是不是刚复位过。

紧接着（约 5 ms 后）就进入正常的 200 Hz 数据流，没有几百毫秒的空档。

不过**刚上电的头几包里，角度字段可能还是 `-1`**：编码器要等第一个完整 PWM 周期
（约 1 ms）才出第一个数，而发包不等人。这是正常的启动瞬态，几毫秒后就会填满。

## 5. 解析示例

### Python

```python
FIELDS = 7

def parse(line: str):
    """返回 [J1..J6 角度(度, 或 None 表示无数据), J7 ADC]，格式不对返回 None。"""
    parts = line.split(",")
    if len(parts) != FIELDS:
        return None                      # "0123456789" 和半行都会落到这里
    try:
        vals = [int(p) for p in parts]
    except ValueError:
        return None

    joints = [None if v < 0 else v / 10.0 for v in vals[:6]]
    return joints, vals[6]


PORT = "/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE8010651-if00"

# 读串口本身另有讲究：内置 open() 拿到的是块缓冲文件对象，在 tty 上
# `for line in fh` 会一直攒到缓冲区满才吐给你，不是一包一行 —— 别那么写。
# 用 pyserial 的 readline；不想引依赖就抄 tools/uart_check.py 里那个
# 基于 os.read + select 的 TermiosPort。
import serial

with serial.Serial(PORT, 115200, timeout=1) as ser:
    for raw in ser:                       # 按 \n 切，CRLF 一起去掉
        got = parse(raw.decode("ascii", "replace").strip())
        if got is None:
            continue
        joints, gripper = got
```

### C

```c
#include <math.h>   /* NAN */

int j1, j2, j3, j4, j5, j6, j7;
int n = sscanf(line, "%d,%d,%d,%d,%d,%d,%d", &j1, &j2, &j3, &j4, &j5, &j6, &j7);
if (n == 7) {
    float deg1 = (j1 < 0) ? NAN : j1 / 10.0f;
    /* ... */
}
```

**不要用 `sscanf` 只判 `n >= 6`**：丢一个字段会让后面的字段整体错位，而且读起来
仍然"像"合法数据。字段数必须是 7。

## 6. 已知坑

1. **没有校验和。** 这一版是纯文本 CSV，没有 CRC、没有帧号。一个被干扰翻转的字节
   会变成一个"看起来合法"的错误数值，静默通过。USB 串口转换器本身不重传也不报错。
   需要校验的场合请用 `Core/Inc/uart_frame.h` 里已经写好的二进制帧格式
   （`AA 55` 帧头 + CRC8 + CRC16）—— 那套编解码已经自测过，但**固件的收发还没接上**，
   当前线上跑的不是它。

2. **没有丢包通知。** 包之间没有序号，丢包只能靠上位机统计收到的包数反推。

3. **角度会在 359.9° → 0.0° 处跳变。** 单圈量程的固有限制，不是丢帧。

4. **`-1` 和"冻住的值"是两种不同的坏法**，见第 2 节。真正判断一路是否活着，
   要比对"这个字段在最近 N 毫秒内是否变过"，而不是看它当前值。

5. **ADC 中段被死区压平**，见第 2 节。

## 7. 自验

仓库里的 [tools/uart_check.py](../tools/uart_check.py) 可以直接验证这包：

```bash
python3 tools/uart_check.py -p /dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE8010651-if00
```

它会按上面规则解析、统计行速率和坏行数，并把前 6 个字段按度数打印出来
（`-1` 显示为 `--`）。`-v` 逐行打印原始内容，`--selftest` 不接硬件自检 CRC。
